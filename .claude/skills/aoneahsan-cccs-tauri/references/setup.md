# Tauri v2 setup and dev workflow

## Prerequisites

| Platform | Needs |
|---|---|
| **macOS** | Xcode (or `xcode-select --install` for desktop-only) |
| **Windows** | Microsoft C++ Build Tools with "Desktop development with C++"; WebView2 (bundled since Win10 1803); `rustup default stable-msvc` |
| **Linux (Debian)** | `libwebkit2gtk-4.1-dev build-essential curl wget file libssl-dev libayatana-appindicator3-dev librsvg2-dev` |

```bash
curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh   # Rust, all platforms
```

## Creating a project

```bash
npm create tauri-app@latest
# frontend: React · TypeScript · Vite
cd my-app && yarn install
```

Register the project's dev port (5900–5999 per the fleet rule) and put it in **both** places or the dev loop
breaks: Vite's `server.port` and `tauri.conf.json`'s `build.devUrl`.

## Configuration reference

```jsonc
{
  "$schema": "https://schema.tauri.app/config/2",
  "productName": "My App",
  "version": "0.1.0",
  "identifier": "com.aoneahsan.myapp",

  "build": {
    "beforeDevCommand": "yarn dev",
    "devUrl": "http://localhost:5910",
    "beforeBuildCommand": "yarn build",
    "frontendDist": "../dist"
  },

  "app": {
    "windows": [{
      "title": "My App",
      "width": 1200, "height": 800,
      "minWidth": 360,          // the app must still work small — same 320-1920 thinking as web
      "resizable": true,
      "center": true
    }],
    "security": {
      // Start strict and open only what is needed. 'unsafe-inline' in style-src
      // is commonly required by CSS-in-JS; scripts should never need it.
      "csp": "default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'"
    }
  },

  "bundle": {
    "active": true,
    "targets": "all",
    "icon": ["icons/32x32.png", "icons/128x128.png", "icons/icon.icns", "icons/icon.ico"]
  }
}
```

`version` may be omitted here to inherit from `package.json` — one source of truth is better than two that
can disagree.

## Dev loop

```bash
yarn tauri dev
```

Builds the Rust core, runs `beforeDevCommand`, waits for `devUrl`, opens the webview, and watches `src-tauri/`
for changes (Rust changes trigger a rebuild and restart; frontend changes hot-reload through Vite).

**This is a long-lived process.** Under the fleet's rules it is run-to-verify only: start it when a change
must be seen working, verify, then kill it. Routine checking is the one-shot gates.

## Gates

```bash
cargo fmt --check --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings
yarn typecheck && yarn lint
yarn tauri build            # the real gate: it compiles and bundles
```

## Debugging

- **Desktop webview:** right-click → Inspect, or Ctrl/Cmd+Shift+I.
- **Rust:** `RUST_LOG=debug yarn tauri dev`, or the `log` plugin for structured output.
- **Mobile:** Safari DevTools (iOS), `chrome://inspect` (Android).

Rust `println!` goes to the terminal running `tauri dev` — but for anything shipped, use the `log` plugin, not
`println!`, mirroring the fleet's no-`console.*` rule on the frontend side.

## Project layout

```
src/                      React app (the house frontend stack)
src-tauri/
  src/main.rs             thin — calls run() from lib.rs
  src/lib.rs              the Builder, commands, setup hooks
  src/commands/           command modules as they multiply
  capabilities/           one JSON per capability
  icons/                  generated by `tauri icon`
  tauri.conf.json
  Cargo.toml
```

Keep `main.rs` thin: the mobile entry point lives in `lib.rs`, so logic there works on both desktop and
mobile without duplication.
