# Custom-made

## Overview

**The standard: nobody can tell a machine made it, because everything in it came from this product.**

Generated work looks generated because it starts from defaults: the likeliest word, the likeliest layout, the likeliest
picture. The fix is to start from the product. The owner's law, 2026-11-04: *"make sure i never have to ask or explain this
ever again for any project."* So never wait to be told, and never ask him. It is part of done, on every model and in every
sub-agent.

## When to use

Always, on anything a person sees or reads, including a one-line error or a seeded row. Load it with the surface's skills
(table below) before the first word or pixel. A fix to existing copy or UI counts.

## The method

1. **The project read.** Three lines from evidence, in the task's notes or your head, never from memory of similar products:
   - *Who and when:* the person, and the job in front of them at this moment.
   - *Its words:* the nouns and verbs this product already uses. Read its strings, `docs/story/` when present, and the trade's
     own language.
   - *Its look:* the tokens, components and class strings of the screen next door. For a new product, its claimed palette and
     design read (`aoneahsan-cccs-design-process`).
2. **Make it from those,** with this product's real objects and believable data.
3. **Take out the tells.** `references/tells.md`, for each surface you touched.
4. **Run the tests.** On the real thing, not on your memory of it.
5. **Report honestly.** Name what still reads as generated. Never claim a detector score.

## The tests

| Test | How | Fails when |
|---|---|---|
| **Swap** | Put another product's name on it | It still makes sense |
| **Read aloud** | Say each line as a colleague at the next desk would | You wouldn't say it, or it explains the product to itself |
| **Looking** | Screenshot it at real widths, beside the screen next door, and look | It doesn't belong, or nothing is clearly the main thing |
| **Why** | Point at each element and say why it's there | The answer is "that's what these usually have" |
| **Stress** | Long names, empty, failed, a phone | It only works on its tidy fixture |

## By surface

| Surface | Made from | Load |
|---|---|---|
| Words | The product's voice and the trade's language | `-copywriting`, `-story-humanize`, `-story-craft` |
| Screens | Its tokens and the screens beside it | `-frontend-design`, `-design-process`, `-design-system`, `-click-dummy` |
| Flows | Its existing paths and the order the work really happens in | `-design-process`, `-interaction-feedback` |
| Emails | One person in the trade writing to another | `-email-campaigns`, `-copywriting` |
| Images | Its mark, fonts, tokens and real captures | `-store-listing-assets`, `-social-post-cards` |
| Docs | What a reader needs next, plainly | `-documentation`, `-markdown`, `-copywriting` |

## New product or existing one

- **A new product of his:** its own world at every level (`~/.claude/rules-detail/frontend-ui-standards.md` §20).
- **An existing, team or client product:** its design language and voice are the material. Belong so completely that nobody can
  tell what's new, then be better than what sits beside it. Never restyle what nobody asked to restyle. Its stack and approved
  dummy win.

## Common mistakes

| Mistake | Instead |
|---|---|
| Treating this as a polish pass at the end | The project read comes first; the tells pass is the check |
| Swapping banned words for synonyms | Rewrite from what actually happens to this person |
| Calling a green build done | Look at it, and read it aloud |
| A new visual style on an old product | Reuse its class strings, then improve the hierarchy |
| Asking him to choose a direction | Decide, write the reason down, let him react |
| "Passes an AI detector" | Report the tests and what still fails them |
