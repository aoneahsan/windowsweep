# Project Understanding — overview

## Purpose

This skill prevents two expensive failures: changing a project before understanding its real constraints, and
asking the owner to repeat decisions already recorded in the repository. It separates evidence, decisions,
and unknowns, then stores new durable knowledge once in the correct canonical file.

## What this skill does

- Establishes an evidence-first reading order before material work.
- Defines precedence when current instructions, project records, feature plans, and global defaults differ.
- Routes durable project, feature, fleet, and session knowledge to different homes.
- Makes material ambiguity block before editing while routine choices follow existing project patterns.
- Scales the discovery gate to the task instead of forcing a full audit for trivial changes.

## When it gets invoked

- "Understand this project before changing anything."
- "I already explained this; remember it next time."
- Starting material work in an unfamiliar or long-unvisited project.
- Resuming a feature after another session or agent.
- Seeing conflicting, stale, or incomplete project guidance.
- Preparing to ask a question that repository evidence may already answer.

## Where it applies

| Scope | Applies |
|---|---|
| Project types | Every ongoing owner project, in any stack |
| Stack override | The project declares its chosen stack; global examples map by concern and never replace it |
| Trivial work | Read nearest guidance and the target only; do not create context documentation as ceremony |
